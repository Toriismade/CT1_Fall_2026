Before We Blink UML

How the p5.js simulation is built: its parts, the states each one moves through, and what happens in one simulation step.

The code uses plain objects and functions, not JavaScript classes. Each class below groups the data and functions that belong together, using their names from the code.

Class diagram

Parts of the system

Round holds everything in one run. Its Time Lords, Angels and crystals exist only for that run, and Reset builds a new Round from the current Settings.

classDiagram
  direction TB

  class Settings {
    +tl: 2..10
    +wa: 2..10
    +fov: 50..200 percent
    +crystals: 3..20
    +tlSpeed: 40..200
    +waSpeed: 40..200
    +storm: 60..300 s
  }

  class App {
    -phase: Phase
    -acc: number
    +startRound()
    +setPaused(on)
    +openStory()
    +finishRound()
    +syncDirty()
  }

  class Round {
    +cfg: Settings
    +time: number
    +elapsed: number
    +delivered: number
    +required: number
    +reach: number
    +halfArc: number
    +winner: TL or WA
    +reason: EndReason
    +drained: number
    +newRound(cfg)
    -scatter(count, spacing, allowed)
    +step(dt)
    -planTimeLords()
    -planAngels()

  }

  class Agent {
    <<abstract>>
    +x: number
    +y: number
    +vx: number
    +vy: number
    +trail: point list
    +steer(tx, ty, maxSpeed, dt)
    +halt()

  class TimeLord {
    +id: number
    +e: energy, starts at 3
    +view: angle
    +carry: ZeitonCrystal or null
    +role: Role
    +aim: angle or null
    +goal: point
    +giveCd: number
    +hasView()
    +inView(x, y, r)
    +giveEnergy(to)
    +touchingAlly()
  }

  class WeepingAngel {
    +id: number
    +cool: 0..10 s
    +seen: boolean
    +goal: point or null
    +canHunt()
  }

  class ZeitonCrystal {
    +x: number
    +y: number
    +state: CrystalState
    +by: TimeLord or null
  }

  class FloatText {
    +x: number
    +y: number

    +draw()

    -drawZone()
    -drawViews()
    -drawZoneLabel()
    -drawConsole()
    -drawCrystals()
    -drawAngels()

  class Hud {

    +statusText()
  }

  class Phase {

    intro

State machine diagrams

How each part changes state

An Angel's 10-second timer keeps running even if a Time Lord is also looking at it. It hunts again only when the timer is done and no view covers it.

Time Lord

stateDiagram-v2
  [*] --> HasView : starts in TARDIS zone
  HasView --> Carrying : touches free crystal
  Carrying --> HasView : reaches console
  HasView --> Out : energy is 0
  Carrying --> Out : energy is 0, drops crystal
  Out --> [*]

Weeping Angel

stateDiagram-v2
  [*] --> Hunting : starts outside zone
  Hunting --> FrozenByView : enters a view
  FrozenByView --> Hunting : leaves every view
  Hunting --> FrozenAfterFeeding : touches Time Lord, takes 1 energy
  FrozenAfterFeeding --> Hunting : 10 s over, not in a view
  FrozenAfterFeeding --> FrozenByView : 10 s over, in a view

Zeiton Crystal

stateDiagram-v2
  [*] --> free
  free --> carried : Time Lord touches it
  carried --> free : carrier runs out of energy
  carried --> delivered : carrier reaches console
  delivered --> [*]

Simulation run

stateDiagram-v2
  [*] --> intro : page loads
  intro --> playing : Start simulation
  playing --> paused : Pause or Story
  paused --> playing : Resume or Reset
  playing --> ended : a winner is set
  ended --> playing : Run again or Reset
Sequence diagram

One simulation step

Each frame, draw() runs as many fixed steps of 1/60 s as the elapsed time needs, then updates the status display and redraws the field as a 1-bit pixel grid. The order inside a step decides the rules: views freeze Angels before any Angel can feed.

sequenceDiagram
  participant S as Sketch
  participant R as Round
  participant T as TimeLord
  participant W as WeepingAngel
  participant C as ZeitonCrystal
  participant A as App
  participant H as Hud

  loop while a full step is due and there is no winner
    S->>R: step(1/60 s)
    R->>R: count down the storm
    opt about every 0.55 s
      R->>T: planTimeLords() sets role, goal, aim
    end
    opt every 0.08 s
      R->>W: planAngels() sets goal
    end
    R->>T: move, spin view, give energy
    R->>W: count down cool, check views, move if free
    R->>W: check for contact with a Time Lord
    W-->>T: take 1 energy, then cool = 10 s
    R->>T: pick up or deliver crystals
    T->>C: update state
    R->>R: check escape, all drained, storm over
  end
  opt a winner is set
    S->>A: finishRound()
  end
  S->>H: updateHud()
  S->>S: fill the pixel buffer, then paint it to the canvas
